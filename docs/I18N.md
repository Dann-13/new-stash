# i18n (español / inglés)

Toda la interfaz se traduce con un módulo propio, sin dependencias externas.

## Cómo funciona

- `src/opencode_usage/i18n.py` guarda `CATALOGS`, un dict con dos idiomas:
  `"es"` y `"en"`. Cada idioma es un dict `clave -> texto`.
- `t(key, **kwargs)` devuelve el texto del idioma activo y lo formatea con
  `.format(**kwargs)`. Si la clave no existe, devuelve la propia clave (no rompe).
- El idioma global se fija **una vez al arrancar**:
  `set_language(resolve_language(...))` en `__main__.py`.

## Elegir idioma (prioridad)

1. CLI: `--lang es|en` (gana siempre).
2. `config.toml`: `language = "es" | "en" | "auto"`.
3. `auto`: mira `LC_ALL`, `LC_MESSAGES`, `LANG`, `LANGUAGE`. Prefijo `es` → español;
   otro valor → inglés; sin pistas → español (defecto).

## Regla de oro

**Ningún texto visible se hardcodea.** Si añades un string que el usuario ve
(tarjeta, leyenda, error, columna, notificación, footer), haz esto:

1. Inventa una clave en inglés, snake_case, con prefijo de dominio:
   `card_*`, `budget_*`, `session_*`, `provider_*`, `col_*`, `md_*`, `ds_*`, `cfg_*`.
2. Añádela a **los dos** catálogos (`es` y `en`). Deben tener las mismas claves.
3. Úsala con `t("clave")` o `t("clave", n=..., pct=...)`.
4. Si lleva placeholders, usa los mismos nombres en ambos idiomas.

Hay un test de **paridad de claves** (`tests/test_i18n.py`): si un idioma tiene una
clave que el otro no, falla. No lo saltes.

## Qué NO se traduce

- Cabeceras del **CSV** (`date,input_tokens,output_tokens,cost_usd`): son datos.
- Nombres de modelos, agentes, proveedores, ids de sesión: vienen de la base.
- Símbolos de gráficas (`█ ▔ ▁ · ■`) y formatos numéricos.

## Detalles que importan

- Los días de la semana son una sola clave `weekdays` con valores separados por
  coma (`"lun,mar,..."`); el widget hace `.split(",")`. Mantén 7 elementos.
- `session_detail` y textos largos se parten en literales concatenados para no
  pasar de 88 columnas (ruff E501).
- En tests, el idioma se resetea a `es` antes y después de cada prueba
  (fixture autouse en `conftest.py`). Si un test necesita inglés, llama
  `set_language("en")` dentro; el fixture lo restaura.

## Añadir un idioma nuevo

1. Añade `"xx": { ... }` a `CATALOGS` con **todas** las claves existentes.
2. Amplía `resolve_language` y las `choices` de `--lang` si aplica.
3. Actualiza el test de paridad y la docs.
